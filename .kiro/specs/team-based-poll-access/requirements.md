# Requirements Document

## Introduction

SprintPulse currently displays all polls to all participants on the /poll page without any filtering or access control. This feature introduces a "Team" concept that allows facilitators to organize polls into teams and restrict participant access using a short PIN code. Participants enter a team PIN to view only the polls belonging to that team, replacing the current unfiltered poll list.

## Glossary

- **Team**: A named grouping entity created by a Facilitator to organize related polls. Each Team has a unique auto-generated PIN.
- **Team_PIN**: A short alphanumeric code (4–6 characters) auto-generated by the System that uniquely identifies a Team. Participants use the Team_PIN to access polls belonging to that Team.
- **Facilitator**: An authenticated user who creates and manages polls and teams via the admin dashboard.
- **Participant**: An unauthenticated user who accesses polls via the /poll page using a Team_PIN.
- **Poll_Service**: The backend service responsible for poll CRUD operations and poll retrieval.
- **Team_Service**: The backend service responsible for team CRUD operations, PIN generation, and PIN validation.
- **Participant_Page**: The /poll page where participants enter a Team_PIN and view filtered polls.
- **Facilitator_Dashboard**: The /admin pages where facilitators manage teams and polls.

## Requirements

### Requirement 1: Team Creation

**User Story:** As a Facilitator, I want to create teams with a name, so that I can organize my polls into logical groups for different participant audiences.

#### Acceptance Criteria

1. WHEN a Facilitator submits a valid team name, THE Team_Service SHALL create a new Team owned by that Facilitator.
2. WHEN a Team is created, THE Team_Service SHALL auto-generate a unique Team_PIN of 4 to 6 alphanumeric characters.
3. THE Team_Service SHALL ensure each generated Team_PIN is unique across all teams in the system.
4. IF a Facilitator submits a team name that is empty or exceeds 100 characters, THEN THE Team_Service SHALL reject the request with a descriptive validation error.
5. THE Team_Service SHALL associate the created Team with the Facilitator who created it.

### Requirement 2: Team Management

**User Story:** As a Facilitator, I want to view, rename, and delete my teams, so that I can keep my team organization up to date.

#### Acceptance Criteria

1. WHEN a Facilitator requests their team list, THE Team_Service SHALL return all teams owned by that Facilitator, ordered by creation date descending.
2. WHEN a Facilitator submits a new name for an existing Team, THE Team_Service SHALL update the Team name.
3. IF a Facilitator attempts to rename a Team with an empty or invalid name, THEN THE Team_Service SHALL reject the request with a descriptive validation error.
4. WHEN a Facilitator deletes a Team, THE Team_Service SHALL soft-delete the Team and disassociate its polls from the deleted Team.
5. IF a Facilitator attempts to manage a Team they do not own, THEN THE Team_Service SHALL reject the request with an authorization error.

### Requirement 3: Poll-Team Assignment

**User Story:** As a Facilitator, I want to assign each poll to a team, so that participants only see polls relevant to their team.

#### Acceptance Criteria

1. WHEN a Facilitator creates a new poll, THE Poll_Service SHALL require the Facilitator to assign the poll to exactly one Team.
2. WHEN a Facilitator edits an existing poll, THE Poll_Service SHALL allow the Facilitator to change the Team assignment.
3. IF a Facilitator attempts to create a poll without a Team assignment, THEN THE Poll_Service SHALL reject the request with a validation error indicating the Team field is required.
4. THE Poll_Service SHALL only allow assignment to Teams owned by the same Facilitator.
5. WHEN a Facilitator requests their poll list, THE Facilitator_Dashboard SHALL display the Team name associated with each poll.
6. WHEN a Facilitator filters polls by Team, THE Poll_Service SHALL return only polls belonging to the selected Team.

### Requirement 4: Participant Access via Team PIN

**User Story:** As a Participant, I want to enter a team PIN to see only the polls for my team, so that I am not overwhelmed by irrelevant polls.

#### Acceptance Criteria

1. WHEN a Participant navigates to the Participant_Page, THE Participant_Page SHALL display a PIN entry form.
2. WHEN a Participant submits a valid Team_PIN, THE Team_Service SHALL validate the PIN and return the associated Team identifier.
3. WHEN a valid Team_PIN is submitted, THE Participant_Page SHALL display only polls belonging to the associated Team.
4. IF a Participant submits an invalid Team_PIN, THEN THE Participant_Page SHALL display an error message indicating the PIN is not recognized.
5. WHEN a valid Team_PIN is accepted, THE Participant_Page SHALL store the PIN in browser localStorage for subsequent visits.
6. WHEN a Participant revisits the Participant_Page with a stored PIN, THE Participant_Page SHALL automatically load polls for the stored Team without requiring re-entry.
7. WHEN a Participant enters a different Team_PIN, THE Participant_Page SHALL replace the stored PIN and display polls for the new Team.
8. THE Participant_Page SHALL provide a visible option for the Participant to switch teams or clear the stored PIN.

### Requirement 5: Team PIN Display for Facilitators

**User Story:** As a Facilitator, I want to see the Team PIN prominently on my dashboard, so that I can easily share it with participants.

#### Acceptance Criteria

1. WHEN a Facilitator views the team management page, THE Facilitator_Dashboard SHALL display the Team_PIN prominently for each Team.
2. THE Facilitator_Dashboard SHALL provide a copy-to-clipboard action for each Team_PIN.
3. WHEN a Facilitator views team details, THE Facilitator_Dashboard SHALL display the Team name and Team_PIN together.

### Requirement 6: Backward Compatibility

**User Story:** As a system administrator, I want existing polls to remain accessible after the team feature is deployed, so that no data is lost during the transition.

#### Acceptance Criteria

1. WHEN the team feature is deployed, THE Poll_Service SHALL retain all existing polls without modification.
2. WHILE existing polls have no Team assignment, THE Participant_Page SHALL display those polls to all participants regardless of Team_PIN entry.
3. THE Poll_Service SHALL require a Team assignment only for newly created polls after the feature is deployed.
4. WHEN a Facilitator edits an existing poll that has no Team assignment, THE Poll_Service SHALL allow but not require adding a Team assignment.
